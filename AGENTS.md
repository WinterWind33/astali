# Astali

## Changelog

`CHANGELOG.md` follows Keep a Changelog. Keep entries short:

- One sentence per entry, ideally under 20 words. Add a second short sentence only when the user would miss it.
- An entry fits on one or two lines of the file. If it needs more, split it or cut it.
- Say what the user gets, not how it works. Leave out the reasons, edge cases and details already obvious from the app.
- No nested sub-lists; split a big feature into a few separate entries instead.
- Bold the feature name for headline features (`**Notes boards**: …`); end every entry with a period.
- Leave out implementation details (file paths, internal modules, exact defaults) unless the user needs them.
- Before adding an entry, reread the section: merge or trim rather than letting it grow.
